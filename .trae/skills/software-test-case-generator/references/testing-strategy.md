# 测试策略

> 本文件是测试用例生成的**唯一规则源**。
> 生成测试点、业务流程、测试用例时**必须**参考本策略。

## 一、测试设计方法优先级

| 优先级 | 方法 | 适用场景 | 覆盖要求 |
| ------ | ---- | -------- | -------- |
| 1 | 场景法（主流程 + 分支 + 异常） | 所有业务功能 | 必须覆盖 |
| 2 | 等价类划分（有效 + 无效） | 输入字段 | 必须覆盖 |
| 3 | 边界值分析 | 数值、类型、长度、时间 | 必须覆盖 |
| 4 | 错误推测法（常见 Bug） | 安全、异常、数据敏感区 | 高优覆盖 |
| 5 | 判定表法 | 多条件组合逻辑 | 按需覆盖 |
| 6 | 正交实验法 | 多配置项组合 | 按需覆盖 |

---

## 二、测试类型覆盖矩阵

| 测试类型 | 说明 | 必须覆盖 P0 功能 | 备注 |
| -------- | ---- | ---------------- | ---- |
| 功能测试 | 验证业务逻辑正确性 | ✅ | 核心 |
| UI 测试 | 验证界面渲染与交互 | 🟡 | 涉及视觉/交互 |
| 异常测试 | 验证错误处理与回滚 | ✅ | 含 4xx/5xx/超时/网络异常 |
| 安全测试 | 验证鉴权、注入、越权、数据泄露 | ✅ | SQL 注入/XSS/越权必测 |
| 性能测试 | 验证响应时间与承载 | 🟡 | 需求给出指标时必测 |
| 兼容测试 | 浏览器 / 终端 / 系统 | 🟡 | 按产品策略执行 |
| 数据测试 | 空值、超长、特殊字符、脚本字符、中文 | ✅ | 所有输入字段必测 |

> 说明：本 Skill 面向功能与界面测试，接口测试仅当需求明确给出接口契约时按需补充。

---

## 三、优先级定义

| 优先级 | 定义 | 覆盖要求 | 示例 |
| ------ | ---- | -------- | ------ |
| P0 | 核心功能，失败将阻塞主流程 | 100% 覆盖 | 登录、支付、下单提交、核心数据写入 |
| P1 | 主要功能分支，影响用户体验 | ≥ 90% 覆盖 | 表单校验、列表筛选、普通增删改查 |
| P2 | 边界 / 异常 / 辅助功能 | ≥ 70% 覆盖 | 超长文本提交、网络异常、超时、键盘操作 |
| P3 | 非功能性、锦上添花 | ≥ 30% 覆盖 | 字体大小、页面美化、冷启动时间 |

## 四、测试数据策略

对所有用户输入字段，必须覆盖以下数据集：

| 数据类型 | 测试数据示例 |
| -------- | ------------ |
| 正常有效 | 典型合法输入 |
| 空值 / 未传 | 空字符串、null、未传字段 |
| 空白字符 | 全空格、制表符、换行符、全角空格 |
| 边界最小 - 1 | 长度 = min - 1 |
| 边界最小 | 长度 = min |
| 边界最大 | 长度 = max |
| 边界最大 + 1 | 长度 = max + 1 |
| 超长 | max × 2、max × 10 |
| 中文字符 | 中文、中文标点、繁体、日文假名 |
| 特殊字符 | `!@#$%^&*()_+{}:"<>?[];',./~` 及竖线 `|` |
| 脚本字符 | `<script>alert(1)</script>`、`<img src=x onerror=alert(1)>` |
| SQL 注入 | `' OR 1=1 --`、`"; DROP TABLE users` |
| 系统命令 | `&& dir`、管道符 + `whoami` |
| Unicode / Emoji | 😀🎉、`\u0000`、代理对 |
| 格式不匹配 | 邮箱填手机号、数字填中文 |
| 大小写敏感 | 英文全大写、全小写、混合 |

## 五、业务流程覆盖矩阵

### 5.1 正向主流程（Happy Path）
- 每个核心功能至少 1 条正向主流程
- 覆盖最典型用户路径

### 5.2 分支流程
- 每个条件判断分支至少 1 条
- 包含 Yes/No、真/假、成功/失败 双向

### 5.3 异常与回退流程
- 网络异常
- 接口超时
- 接口 4xx / 5xx
- 提交中中断
- 页面刷新 / 关闭
- 数据冲突 / 并发编辑

### 5.4 逆向流程
- 取消操作
- 返回上一步
- 放弃已填数据
- 关闭页面

### 5.5 用例规模参考（参考值，可按项目调整）
- 每条可验证需求：3~6 条用例（功能 1~2 + 边界 1~2 + 异常 1 + 安全 0~1）
- P0 功能用例数不低于该模块总量的 40%
- 单个 CSV 建议控制在 20~80 条；超过 80 条时按子功能拆分文件
- 同一字段的同类校验可合并为一条用例的多组测试数据，不重复堆量

## 六、公共规则自动合并策略

在生成测试用例前，从需求文档中识别业务规则，按以下关键词自动匹配对应测试维度（**命中即覆盖，多项累加**）。

### 6.1 业务规则关键词映射

| 需求中出现以下关键词 | 自动覆盖的测试维度 |
| ------------------ | ------------------ |
| 分页、列表、每页、页大小、页码 | 分页功能（默认条数、自定义条数、快速翻页） |
| 脱敏、加密、敏感 | 数据脱敏校验 |
| 上传、下载、附件、文件 | 文件上传/下载（格式限制、大小限制，数值以需求为准） |
| 日期、时间、日期范围、年月、提交时间、更新时间 | 日期格式校验（以需求规定格式为准） |
| 必填、必选、不能为空、提交校验 | 必填项校验 |
| 列表、倒序、排序、默认加载、空数据、空提示 | 列表展示排序、空数据提示 |
| 保存、暂存、草稿 | 保存按钮状态流转 |
| XSS、SQL注入、越权、安全、CSRF、注入 | 安全漏洞防范（XSS/CSRF/SQL注入） |
| 性能、响应时间、超时、加载慢、并发 | 性能响应时间校验（指标以需求为准） |
| 网络异常、导出中断、断网、重试 | 网络异常处理和提示 |
| 权限、角色、登录、授权、操作范围 | 角色权限控制 |

### 6.2 通用校验规则关键词映射

| 需求中出现以下关键词 | 自动覆盖的测试维度 |
| ------------------ | ------------------ |
| 输入框、文本框、输入、为空、非空、数字输入 | 输入框校验（非空、数字、邮箱、手机号、URL 格式） |
| 表单、必填项、提交、错误提示、成功提示 | 表单校验（必填项、格式验证、逻辑验证、提示信息） |
| 按钮、点击、禁用、加载、重复点击、重复提交 | 按钮校验（禁用态、加载态、防重复提交） |
| 页面加载、响应、兼容性、浏览器、Chrome、Firefox、Safari、Edge、PC、平板、手机 | 页面校验（加载时间、响应时间、浏览器兼容、响应式） |

> **注**：若未明确提及但涉及输入 / 上传 / 列表 / 表单等通用场景，默认加载通用校验规则全部子项。
> 需求自身写明的具体数值（如 ≤500M、≤2秒、每页 10 条）优先于本策略的通用描述。
